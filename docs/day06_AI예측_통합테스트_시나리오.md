# 🧪 Day06 AI 예측 통합 테스트 시나리오

- 대상: 승인 회원용 AI 예측 `POST /api/v1/medical-records/{record_id}/predict` 및 결과 목록 `GET /api/v1/medical-records/{record_id}/analyses`
- 자동화 테스트: `tests/test_ai_analyses.py`
- 검증 범위: HTTP 라우트 → 인증 의존성 → 예측 서비스 → 응답 스키마
- 격리 범위: 실제 MySQL, AI 가중치 파일, 업로드 파일 저장은 테스트에서 모의 처리
- 모델 예측은 모의 함수로 대체하지만, 결과 재사용·상태 코드·응답 JSON은 실제 API와 서비스 코드를 통과해 검증

## 실행

프로젝트 루트에서 다음 명령을 실행한다.

```bash
uv run pytest -q tests/test_ai_analyses.py
```

전체 테스트는 다음 명령으로 확인한다.

```bash
uv run pytest -q
```

## 자동화 시나리오

| # | 시나리오 | 확인 내용 |
|---|---|---|
| 1 | 승인된 회원이 아직 저장된 예측이 없는 진료 기록을 예측 | `201 Created`, 결과 필드와 모델명·히트맵 URL·confidence 값, 예측 및 히트맵 생성 1회 |
| 2 | 예측 직후 같은 기록의 분석 목록을 조회 | `200 OK`, 방금 저장된 결과가 목록에 포함 |
| 3 | 같은 기록에서 동일 모델로 다시 예측 | `200 OK`, 기존 분석 결과를 반환하고 모델 추론·DB 저장은 재실행하지 않음 |
| 4 | 인증 없이 분석 목록 조회 | `401 Unauthorized` |
| 5 | 승인 대기 회원이 분석 목록 조회 | `403 Forbidden`, `관리자 승인 후 이용할 수 있습니다.` |
| 6 | 존재하지 않는 진료 기록 예측 | `404 Not Found`, `진료 기록을 찾을 수 없습니다.` |
| 7 | 진료 기록에 X-Ray가 없거나 실제 이미지 파일이 없음 | `404 Not Found`, `X-Ray 이미지 파일을 찾을 수 없습니다.` |
| 8 | 모델이 준비되지 않은 상태에서 예측 | `503 Service Unavailable`, `AI 모델이 준비되지 않았습니다.` |
| 9 | 예측 결과가 아직 없는 진료 기록의 목록 조회 | `200 OK`, 빈 배열 `[]` |
| 10 | 존재하지 않는 진료 기록의 분석 목록 조회 | `404 Not Found`, `진료 기록을 찾을 수 없습니다.` |

## 수동 확인 (서버·실제 모델 사용)

실제 UI와 모델 파일까지 확인해야 할 때만 수행한다. 실행 전 DB 연결과 모델 가중치 파일 구성이 되어 있는지 확인한다.

1. `uv run fastapi dev app/main.py`로 서버를 시작하고 승인된 회원으로 로그인한다.
2. 진료 기록에 유효한 PNG/JPEG X-Ray가 등록되어 있는지 확인한다.
3. 진료 기록 상세 페이지에서 AI 예측을 요청한다.
4. 첫 요청은 `201`, 같은 기록의 동일 모델 재요청은 `200`인지 확인한다.
5. 예측 결과의 폐렴 여부, 신뢰도(0~100), AI 모델명 및 히트맵 표시를 확인한다.
6. 분석 목록을 다시 조회해 결과가 저장되어 있고 최신순으로 표시되는지 확인한다.
7. 기록이 없는 ID, 이미지가 없는 기록, 승인 대기 회원으로 각각 요청해 위 자동화 표의 오류 응답을 확인한다.

> 수동 확인의 실제 모델 출력은 X-Ray 입력과 가중치에 따라 달라진다. 폐렴 여부의 정답 판정이 아니라 응답 형식·상태 코드·저장 및 재사용 동작을 확인한다.
