# 4️⃣ EC2 인스턴스의 Swap Memory 설정하기

## 🤔 왜 필요한가

- t3.micro는 RAM이 **1GiB**뿐임
- 아무것도 띄우지 않은 상태에서도 **909Mi 중 357Mi**를 이미 사용 중이었음
- 우리 서버는 MySQL(약 400MB) + torch와 AI 모델 3개(약 700MB 이상) + Nginx를 함께 올림
- RAM이 가득 차면 OOM Killer가 컨테이너를 강제 종료함 → **디스크 일부를 메모리처럼 쓰는 스왑**으로 버팀
- 대신 디스크는 RAM보다 느려서 성능이 떨어질 수 있음 (특히 첫 AI 예측)

## ✅ 진행

```bash
sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile && echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab && free -h
```

| 명령 | 하는 일 |
|---|---|
| `fallocate -l 4G /swapfile` | 디스크에 4GB짜리 빈 파일 생성 |
| `chmod 600 /swapfile` | root만 읽고 쓸 수 있게 막음 |
| `mkswap /swapfile` | 그 파일을 스왑 공간으로 포맷 |
| `swapon /swapfile` | 스왑 켜기 |
| `/etc/fstab`에 추가 | 재부팅해도 스왑이 자동으로 켜지게 |
| `free -h` | 결과 확인 |

## 📋 결과

- [x] **Swap 4.0Gi** 활성화

## 💡 배운 점

- 스왑 크기는 RAM과 디스크 여유를 보고 정함. 디스크를 30GiB로 잡아 둬서 4GB를 넉넉하게 쓸 수 있었음
- 스왑은 서버가 죽지 않게 해 주는 안전장치일 뿐 RAM을 대신하지는 못함. 실제 서비스라면 메모리가 큰 인스턴스를 써야 함
