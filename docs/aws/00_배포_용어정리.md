# ☁️ 배포 시 알아둬야 하는 용어

> AWS 배포 추가 과제를 시작하기 전에 배포에 쓰이는 도구와 서비스를 정리함

## 🗺️ 한눈에 보기

```
사용자 ──http──▶ Nginx ──▶ Uvicorn ──▶ FastAPI 앱 ──▶ MySQL
                (80)      (8000)
               └──────────── Docker Compose로 한 번에 실행 ────────────┘
               └──────────────────── AWS EC2 (가상 서버) ──────────────────┘
```

| 용어 | 한 줄 설명 | 우리 프로젝트에서 |
|---|---|---|
| Nginx | 요청을 가장 먼저 받는 웹 서버 | `nginx` 컨테이너, 80번 포트로 받아 FastAPI로 전달 |
| Uvicorn | FastAPI를 실행하는 ASGI 서버 | `uvicorn app.main:app` |
| Docker | 코드와 실행 환경을 컨테이너로 묶는 도구 | `app/Dockerfile`로 만든 이미지 |
| Docker Compose | 여러 컨테이너를 한 번에 실행·관리 | `docker-compose.prod.yml` (nginx + fastapi + mysql) |
| AWS | 클라우드 컴퓨팅 플랫폼 | 서버를 빌리는 곳 |
| EC2 | AWS에서 빌리는 가상 서버 | t3.micro (Ubuntu) 1대 |

## 1. Nginx

사용자가 웹사이트에 접속했을 때 **가장 먼저 요청을 받는 웹 서버**임.  
비동기 이벤트 기반 구조라서 적은 자원으로 수만 개의 동시 연결을 빠르게 처리함.

### 주요 기능

| 기능 | 설명 |
|---|---|
| Reverse Proxy | 사용자는 도메인(`https://api.example.com`)만 알면 되고, Nginx가 그 요청을 내부 FastAPI 서버(`uvicorn:8000`)로 전달함 |
| 보안 | HTTPS(SSL 인증서) 처리, 비정상 요청 차단, 요청 크기 제한 |
| 부하 분산 | 로드 밸런싱. FastAPI 서버가 여러 대일 때 트래픽을 나눠 줘서 안정성을 높임 |
| 정적 파일 처리 | 이미지·CSS·JS 요청은 FastAPI까지 보내지 않고 Nginx가 바로 응답함 |

> 💡 요청 크기 제한 기본값은 1MB임. X-Ray 사진 업로드가 막히지 않도록 `client_max_body_size`를 늘려야 함

## 2. Uvicorn

FastAPI 같은 파이썬 비동기 웹 프레임워크를 위한 **빠르고 가벼운 ASGI 웹 서버**임.  
FastAPI는 기본적으로 Uvicorn을 통해 실행됨.

### ASGI (Asynchronous Server Gateway Interface)

- **웹 서버와 파이썬 애플리케이션이 어떻게 대화할지 정한 규칙**
- 웹 서버(Nginx)와 파이썬 앱(FastAPI) 사이의 통역사 역할
- Uvicorn은 ASGI 규칙에 따라 요청과 응답을 주고받게 해 줌

### 왜 ASGI가 필요한가?

- Nginx는 ASGI를 직접 이해하지 못함 → 중간에 ASGI 서버인 Uvicorn이 필요함
- WSGI와 비교

| 구분 | WSGI | ASGI |
|---|---|---|
| 처리 방식 | 동기 | 비동기 |
| 동작 | 요청 하나가 끝나야 다음 요청을 처리 | 작업 완료를 기다리지 않고 다음 코드를 실행 |
| 장점 | 단순함 | 여러 작업을 동시에 처리해 응답성이 좋음 |

```
사용자 → Nginx(웹 서버) → Uvicorn(ASGI 서버) → FastAPI(앱)
```

## 3. Docker

애플리케이션을 빠르게 구축·테스트·배포할 수 있는 **컨테이너 기반 오픈소스 가상화 플랫폼**임.  
코드, 런타임, 라이브러리 같은 실행 환경을 **컨테이너**라는 표준 단위로 묶어서, 개발 환경과 운영 환경의 차이 없이 어디서나 똑같이 실행되게 함.

### 구성 요소

| 구성 요소 | 설명 |
|---|---|
| 이미지(Image) | 컨테이너를 만들기 위한 실행 환경 묶음 (설계도·밀키트) |
| 컨테이너(Container) | 이미지를 실행한 것 (실제로 돌아가는 프로그램) |
| 볼륨(Volume) | 컨테이너가 지워져도 데이터를 남기는 저장 공간 |
| 네트워크(Network) | 컨테이너끼리 통신하는 길 |
| 도커 엔진(Docker Engine) | 이미지를 빌드하고 컨테이너를 실행하는 핵심 프로그램 |

### 도커를 사용하는 이유

- **경량화**: VM(가상 머신)보다 가벼워서 자원을 효율적으로 씀
- **빠른 배포**: 컨테이너가 바로 시작되고 환경 설정이 간편함
- **자동화**: 개발·배포·업데이트를 자동화하기 좋아 마이크로서비스 구조에 적합함
- **표준화**: 도커 레지스트리(Docker Hub 등)에 이미지를 저장하고 어디서든 받아 쓸 수 있음

## 4. Docker Compose

여러 컨테이너로 이루어진 애플리케이션을 **하나의 서비스로 정의하고, 명령어 하나로 생성·실행·관리**하는 도구임.  
FastAPI, Nginx, DB 같은 컨테이너를 한 번에 실행하고 관리하는 **지휘자** 역할을 함.  
설정 파일(`docker-compose.yml`) 하나가 복잡한 `docker run` 명령어들을 대신함.

### Docker Compose를 사용하는 이유

| 이유 | 설명 |
|---|---|
| 설정 간소화 | 컨테이너마다 `docker run` 하는 대신 `docker compose up` 한 번으로 전체 실행 |
| 환경 일관성 | 모든 설정이 yml 파일에 있어서 개발·테스트·운영 환경을 똑같이 만들고 공유하기 쉬움 |
| 쉬운 관리 | 서비스·네트워크·볼륨을 한 파일에서 관리, 묶음으로 시작·중지·재시작 |
| 네트워크 관리 | 서비스 이름을 호스트명처럼 써서 통신 (예: fastapi에서 DB 주소 = `mysql`) |

## 5. AWS (Amazon Web Services)

아마존이 운영하는 **세계 1위 클라우드 컴퓨팅 플랫폼**임.  
서버, 스토리지, 데이터베이스 등 200개가 넘는 IT 인프라 서비스를 인터넷으로 **쓴 만큼 내는 종량제(Pay-as-you-go)** 방식으로 제공함.

### AWS를 사용하는 이유

| 이유 | 설명 |
|---|---|
| 비용 효율성 | 장비를 미리 살 필요 없이 쓴 만큼만 지불 → 고정 비용이 가변 비용이 됨 |
| 유연한 확장성 | 트래픽에 따라 클릭 몇 번으로 서버 용량을 늘리고 줄임 |
| 안정성과 보안 | 전 세계 데이터 센터 기반, 높은 수준의 물리·네트워크 보안 |
| 다양한 서비스 | 컴퓨팅, DB, 스토리지, AI/ML, IoT 등 200개 이상 |
| 글로벌 인프라 | 여러 지역(Region)의 데이터 센터로 빠르고 일관된 서비스 |
| 신속한 혁신 | 인프라 관리 부담이 줄어 개발에 집중 → 출시 속도가 빨라짐 |

> ⚠️ 종량제라서 켜둔 만큼 요금이 나감. 과제가 끝나면 사용한 리소스(EC2, 볼륨 등)를 반드시 정리해야 함

## 6. EC2 (Elastic Compute Cloud)

AWS에서 제공하는 **가상 서버(인스턴스) 대여 서비스**임.  
컴퓨터를 빌리듯 CPU·메모리·스토리지를 필요한 만큼 빌려 원격으로 접속해 쓰고, 쓴 시간만큼 비용을 냄.

### 주요 특징

| 특징 | 설명 |
|---|---|
| 컴퓨팅 자원 임대 | 하드웨어 구매 없이 가상 서버를 바로 생성 |
| 확장성(Elasticity) | 요구사항에 따라 서버 용량을 유연하게 조절 |
| 비용 효율성 | 사용한 시간만큼만 지불, 초기 투자 비용 절감 |
| 다양한 인스턴스 유형 | CPU·메모리·네트워크·스토리지에 최적화된 여러 사양 중 선택 |
| 높은 제어권 | 보안, 네트워킹, 스토리지를 직접 설정 |

- **주요 용도**: 백엔드 서버 배포, DB 호스팅, 웹 애플리케이션 실행, 개발·테스트 환경 구축
- **우리 과제**: 프리 티어 t3.micro(RAM 1GB)를 써서 메모리가 부족함 → 스왑 메모리를 설정해서 서버를 띄움

## 📌 한 줄 요약

> **EC2**라는 빌린 서버 위에서, **Docker Compose**가 **Nginx → Uvicorn(FastAPI) → MySQL** 컨테이너를 한 번에 띄우고, 사용자 요청은 Nginx가 먼저 받아 FastAPI로 넘겨줌
