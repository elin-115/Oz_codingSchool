# 5️⃣ Docker image Build & Push

- 담당: 김지연
- 날짜: 2026-11-02

## ⚠️ 가이드와 다르게 한 점: ARM 맥 → amd64 빌드

| 컴퓨터 | 아키텍처 |
|---|---|
| 맥 (M칩) | ARM (`aarch64`) |
| EC2 t3.micro | x86 (`amd64`) |

- 가이드는 `docker-compose.yml`에 `image:`를 넣고 compose로 빌드·푸시하는 방식
- 맥에서 그대로 빌드하면 **ARM 이미지**가 올라가서 EC2에서 `exec format error`로 실행되지 않음
- compose에 `platform: linux/amd64`를 넣는 방법도 있지만, 그러면 로컬 개발(`docker compose up`)까지 에뮬레이션으로 느려짐
- 그래서 **compose는 건드리지 않고 `docker buildx`로 amd64를 지정해 빌드와 푸시를 한 번에** 진행함

## ✅ 진행

### 사전 확인

| 항목 | 상태 |
|---|---|
| Docker Hub 연결 | ✅ |
| buildx | ✅ `linux/amd64` 빌드 지원 |
| 맥 Docker Hub 로그인 | ✅ (3단계 웹 로그인) |

### 빌드 + 푸시

```bash
cd ~/Desktop/Oz_codingSchool
docker buildx build --platform linux/amd64 -f app/Dockerfile -t elin115/oz-backoffice:latest --push .
```

| 옵션 | 뜻 |
|---|---|
| `--platform linux/amd64` | EC2(x86)에서 돌아가는 이미지로 빌드 (맥에선 에뮬레이션이라 오래 걸림) |
| `-f app/Dockerfile` | Stage 8에서 만든 Dockerfile 사용, 빌드 context는 루트(`.`) |
| `-t elin115/oz-backoffice:latest` | `Docker Hub 유저이름/저장소:태그` |
| `--push` | 빌드가 끝나면 바로 Docker Hub에 업로드 |

- torch 설치 단계와 업로드 단계가 오래 걸림
- 리눅스에서는 `pyproject.toml` 설정(`[tool.uv.sources]`)대로 **torch CPU 전용**이 설치됨

## 🔍 푸시 결과 확인

### 플랫폼

```bash
docker buildx imagetools inspect elin115/oz-backoffice:latest
```

```
Platform:    linux/amd64
Platform:    unknown/unknown   ← 빌드 기록(attestation) 메타데이터, 이미지 아님
```

### 이미지 안에 비밀 정보가 없는지

공개 이미지라서 받아서 직접 열어 봄.

```bash
docker run --rm --platform linux/amd64 --entrypoint sh elin115/oz-backoffice:latest -c 'ls -A /app; uname -m'
```

| 확인 항목 | 결과 |
|---|---|
| 아키텍처 | `x86_64` ✅ |
| 크기 | 1.97GB |
| torch | `2.14.1+cpu` ✅ (로컬과 같은 버전) |
| `/app` | `.env.example`, `.venv`, `alembic`, `alembic.ini`, `app`, `pyproject.toml`, `static`, `uv.lock`, `worker` |
| `.env` | 없음 ✅ (`.env.example`만 있음, 원래 커밋되는 예시 파일) |
| 모델 파일 `*.pt` | 없음 ✅ → `worker/models/`가 비어 있어서 6단계에서 볼륨으로 연결해야 함 |
| 키 `*.pem` | 리눅스 기본 공개 인증서(`/etc/ssl/certs`)만 있음 ✅ |

- Stage 8에서 만든 `.dockerignore`가 `.env`, `*.pt`, docs 등을 잘 막고 있음을 확인함

## 💡 배운 점

- **이미지는 빌드한 컴퓨터의 CPU 구조를 따라감.** 맥(ARM)에서 만든 이미지를 x86 서버에서 쓰려면 `--platform`을 지정해야 함
- 가이드 방식이 우리 환경에 맞지 않으면 **이유를 확인하고 바꾸는 것**도 배포 과정의 일부임
- 공개 레지스트리에 올리는 이미지는 **푸시 후 직접 열어서** 비밀 정보가 없는지 확인해야 함
