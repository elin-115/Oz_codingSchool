# 6️⃣ AWS EC2에 배포에 필요한 파일 작성/복사하기

## 📝 작성한 파일

| 파일 | 역할 | 커밋 |
|---|---|---|
| `docker-compose.prod.yml` | 서버에서 nginx + fastapi + mysql을 한 번에 실행 | ✅ |
| `nginx/default.conf` | 80번 포트로 받은 요청을 fastapi로 전달 | ✅ |
| `.prod.env` | 서버용 환경 변수 (DB 비밀번호, SECRET_KEY) | ❌ (`.gitignore`의 `*.env`) |

### 서버 폴더 구조

scp로 올리면 서버에는 아래처럼 놓임. 파일 안의 경로(`./nginx/...`, `./models`)는 이 구조 기준으로 씀.

```
/home/ubuntu/ai_project/
├── docker-compose.yml   ← docker-compose.prod.yml
├── .env                 ← .prod.env
├── nginx/default.conf
├── models/              ← AI 모델 .pt 파일 3개
└── media/               ← 업로드 사진·히트맵 (컨테이너가 켜질 때 자동 생성)
```

## 1. `docker-compose.prod.yml`

로컬 개발용 `docker-compose.yml`을 복사해서 서버용으로 바꿈.

| 서비스 | 로컬(`docker-compose.yml`) | 서버(`docker-compose.prod.yml`) | 이유 |
|---|---|---|---|
| fastapi | `build:`로 직접 빌드 | `image: elin115/oz-backoffice:latest` | 5단계에서 Docker Hub에 올린 이미지를 받아옴 |
| fastapi | `uvicorn ... --reload` | `--reload` 제거 | 서버에선 코드가 바뀌지 않음 |
| fastapi | `ports: 8000:8000` | 제거 | 외부 요청은 nginx로만 받음. 컨테이너끼리는 포트를 열지 않아도 서비스 이름으로 통신 |
| fastapi | 코드 폴더 마운트, `venv_volume` | 제거 | 코드는 이미지 안에 들어 있음 |
| fastapi | - | `./models:/app/worker/models` | 이미지에서 제외한 AI 모델을 서버 폴더에서 연결 |
| fastapi | - | `./media:/app/media` | 업로드 사진·히트맵을 서버에 남김 (컨테이너를 다시 만들어도 유지) |
| 3개 모두 | - | `restart: unless-stopped` | 서버가 재부팅돼도 다시 켜짐 |
| mysql | `ports: 3306:3306` | 제거 | DB는 외부에 열지 않음 |
| nginx | - | 새로 추가 | 아래 참고 |

nginx 서비스

```yaml
  nginx:
    image: nginx:stable-alpine          # 공식 nginx, stable 버전, 가벼운 alpine 기반
    restart: unless-stopped
    ports:
      - "80:80"                          # 서버 80 → 컨테이너 80 (밖에서 들어오는 유일한 입구)
    depends_on:
      fastapi:
        condition: service_healthy       # fastapi가 준비된 뒤 켜짐
    volumes:
      - ./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro   # 서버 설정 파일을 컨테이너에 읽기 전용으로 연결
```

### 작성하면서 막힌 것

| 에러 / 문제 | 원인 | 해결 |
|---|---|---|
| `dependency cycle detected: nginx -> nginx` | `depends_on`에 nginx 자기 자신을 씀 | 기다릴 대상을 **fastapi**로, `condition: service_healthy` |
| nginx 설정이 적용 안 될 뻔함 | 볼륨에 컨테이너 경로만 씀 → 빈 임시 볼륨이 생김 | 볼륨은 항상 `서버경로:컨테이너경로` 형식 |
| `required variable DB_PASSWORD is missing a value` | `.prod.env`를 가이드 예시로 덮어써서 DB 비밀번호 키가 사라짐 | 우리 프로젝트에 필요한 키로 다시 정리 (아래 3번) |

## 2. `nginx/default.conf`

```nginx
# fastapi 서버 업스트림 설정
upstream fastapi {
    server fastapi:8000;              # compose 서비스 이름:포트
}

server {
    listen 80;
    client_max_body_size 10M;         # X-Ray 업로드 (nginx 기본값 1MB면 413 에러)

    location / {
        proxy_pass http://fastapi;    # 위 upstream으로 전달
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;      # 스왑 때문에 AI 예측이 느려도 504가 나지 않게
        proxy_buffering off;
    }
}
```

### 가이드 예시와 다르게 한 점

- 가이드 예시에는 `/static/`, `/media/`를 nginx가 `/vol/web`에서 직접 응답하는 블록이 있음
- 우리 compose에는 nginx에 그 폴더를 연결하지 않았고, FastAPI가 `app.mount("/static")`, `app.mount("/media")`로 직접 서빙함
- 그대로 두면 404가 나서 **두 블록을 지우고** 모든 요청을 FastAPI로 넘김

### 막힌 것

| 에러 | 원인 | 해결 |
|---|---|---|
| `invalid URL prefix in default.conf:12` | `proxy_pass fastapi;` → upstream 이름에도 `http://`가 필요 | `proxy_pass http://fastapi;` |

## 3. `.prod.env`

`.env.example`을 복사해서 시작함. 키만 적고 값은 문서에 남기지 않음.

| 키 | 값 |
|---|---|
| `DB_HOST` | `mysql` (compose에서도 덮어쓰지만 헷갈리지 않게) |
| `DB_PORT`, `DB_USER`, `DB_NAME` | `.env.example`과 동일 |
| `DB_PASSWORD`, `DB_ROOT_PASSWORD`, `SECRET_KEY` | **새로 생성한 랜덤 값** (세 값 모두 다르게) |

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

- `.env.example`은 GitHub에 공개된 파일이라 예시 값을 그대로 쓰면 누구나 비밀번호를 알 수 있음
- `SECRET_KEY`가 빠지면 에러 없이 `app/core/config.py`의 기본값(공개된 값)으로 동작해서 로그인 토큰을 위조당할 수 있음
- 가이드 예시의 `REDIS_*`, `DOCKER_WEB_IMAGE`, `DOCKER_AI_WORKER_IMAGE`는 Redis·AI 워커를 별도 컨테이너로 둔 구조용이라 **사용하지 않음** (우리는 AI 모델을 fastapi 안에서 실행)
- DB 비밀번호는 **MySQL을 처음 켜기 전에** 정해야 함. 한 번 띄우면 볼륨에 저장된 비밀번호가 유지됨

## ✅ 작성 후 검사

```bash
# compose 문법 (출력에 비밀번호가 나오지 않게 --quiet)
docker compose -f docker-compose.prod.yml --env-file .prod.env config --quiet && echo OK

# nginx 설정 문법
docker run --rm -v "$PWD/nginx/default.conf:/etc/nginx/conf.d/default.conf:ro" --add-host fastapi:127.0.0.1 nginx:stable-alpine nginx -t
```

| 검사 | 결과 |
|---|---|
| compose `config` | `OK` |
| nginx `-t` | `test is successful` |
| `.prod.env` 비밀 값 | 예시 값과 다름, 세 값 서로 다름 |
| `git status` | `.prod.env` 안 나옴 (커밋 대상 아님) |

> 💡 `config` 검사는 yml 문법만 확인함. 볼륨 경로, `proxy_pass` 형식처럼 내용이 맞는지는 `nginx -t`나 실제 실행으로 따로 확인해야 함

## 📤 EC2로 복사 (맥 터미널)

```bash
# 서버에 폴더 먼저 만들기 (없으면 scp가 실패함)
ssh -i 키파일.pem ubuntu@EC2_IP "mkdir -p ~/ai_project/nginx ~/ai_project/models"

cd ~/Desktop/Oz_codingSchool
scp -i 키파일.pem docker-compose.prod.yml ubuntu@EC2_IP:/home/ubuntu/ai_project/docker-compose.yml
scp -i 키파일.pem .prod.env ubuntu@EC2_IP:/home/ubuntu/ai_project/.env
scp -i 키파일.pem nginx/default.conf ubuntu@EC2_IP:/home/ubuntu/ai_project/nginx/default.conf
scp -i 키파일.pem worker/models/best_model_*_fold1.pt ubuntu@EC2_IP:/home/ubuntu/ai_project/models/
```

- `docker-compose.prod.yml` → 서버에서는 `docker-compose.yml`, `.prod.env` → `.env`로 이름을 바꿔서 올림 (서버에서 `docker compose up`만 치면 되게)
- 모델은 가이드 예시(`pneumonia_model.pth` 1개)와 달리 우리가 쓰는 **fold1 파일 3개** (densenet121 28MB, efficientnet_b0 16MB, resnet50 94MB)

### 복사 확인

서버와 맥의 파일 지문(md5)을 비교해서 6개 모두 같은 것을 확인함.

```bash
# 서버
md5sum docker-compose.yml nginx/default.conf .env models/*.pt
# 맥
md5 -r docker-compose.prod.yml nginx/default.conf .prod.env worker/models/best_model_*_fold1.pt
```

그리고 `.env`를 나만 읽을 수 있게 권한을 바꿈 (`644` → `600`).

```bash
chmod 600 ~/ai_project/.env
```

## 💡 배운 점

- 같은 앱이라도 **로컬용 compose와 서버용 compose는 목적이 다름**. 로컬은 코드 수정 즉시 반영, 서버는 안정적인 실행과 최소한의 포트 공개가 목표
- 가이드 예시는 다른 구조(Redis, AI 워커 분리, nginx 정적 파일)를 기준으로 하므로 **우리 프로젝트에 맞는 부분만** 가져와야 함
- 비밀 값은 문서·캡처·채팅에 남기지 않고, 글자 수나 예시 값과 같은지만 비교해서 확인할 수 있음
