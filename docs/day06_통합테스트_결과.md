## 💡 개선 제안

### 1. 시간 9시간 차이 고치기 (김지연) ✅ 반영

| 방법 | 바꾸는 곳 | 장점 | 단점 |
|---|---|---|---|
| **A. 응답에 UTC 표시 붙이기 (추천)** | 응답 스키마 (`ai_analyses`, `medical_records`, `patients`) + 회원 응답 | DB·프론트 그대로. 응답이 `...T00:14:23Z`가 되면 브라우저가 한국 시각으로 바꿔 보여줌 | 시각을 내보내는 스키마를 빠짐없이 바꿔야 함 |
| B. 프론트에서 `Z` 붙여 읽기 | `static/pages.js`의 `new Date(...)` + 회원 화면 | 가장 빨리 고칠 수 있음 | 서버 응답은 여전히 애매해서 다른 화면·앱에서 다시 생김 |
| C. 한국 시각으로 저장 | 모델 기본값, MySQL 시간대, 기존 데이터 | 화면과 DB 값이 같아 보임 | 기존 데이터와 섞임. 서버마다 시간대가 다르면 다시 꼬임 |

A 방법 예시 — 공통 타입을 만들어 응답 스키마의 `created_at`에 씀

```python
# app/schemas/common.py
from datetime import UTC, datetime
from typing import Annotated

from pydantic import AfterValidator

# DB에서 읽은 시간대 없는 시각에 "이건 UTC"라고 표시만 붙임 (값은 그대로)
UTCDatetime = Annotated[datetime, AfterValidator(lambda v: v.replace(tzinfo=UTC) if v.tzinfo is None else v)]
```

```python
# app/schemas/ai_analyses.py 등
created_at: UTCDatetime   # 기존: created_at: datetime
```

- 응답이 `"created_at": "2026-10-29T00:14:23Z"`로 바뀜 (로컬에서 확인함) → 프론트 수정 없음, DB 마이그레이션 없음
- 모든 화면의 시각이 바뀌는 변경이라 팀 논의 후 한 PR로 진행

### 2. 브라우저 캐시 막기 (김지연) ✅ 반영

### 3. AI 결과를 "참고용"으로 표시 (김지연) ⏳ 기준값 논의

- 같은 Positive라도 99.85%와 61.89%가 표에서 똑같이 보이고, X-Ray가 아닌 사진도 판정함
- confidence는 "폐렴과 정상 중 어디에 더 가까운가"이지 "얼마나 믿을 만한가"가 아님

- 현재: "휴대폰 번호는 하이픈 없이 01로 시작하는 10-11자리 숫자여야 합니다."
- 제안: "휴대폰 번호는 하이픈 없이 010으로 시작하는 11자리 숫자여야 합니다."
- 사유: "01로 시작하는 10-11자리"는 한 번에 읽기 어렵고, 2G 서비스 종료(2021년)와 01X → 010 자동연결 종료(2022년 1월)로 개인 휴대폰 번호는 사실상 010 + 11자리로 일원화됨
- 추가 아이디어: 칸 이름 `연락처` → `휴대폰 번호`, 또는 앞자리를 드롭다운으로 선택
- 주의: 같은 검사 규칙(`PhoneType`)을 회원가입·내 정보 수정도 쓰므로, 규칙을 바꾸면 회원 쪽도 같이 바뀜
