### 의료진 계정 만들기

환자 등록·진료기록 등록은 **부서가 의료진(`medical team`)인 승인된 회원**만 가능. 어드민이어도 개발·연구 부서면 403이 정상.

1. 회원가입 (부서: **의료진**, 예: `doctor.test@example.com`)
2. 어드민 계정 **회원 관리**에서 권한을 `staff`로 변경. 또는 DBeaver SQL 에디터에서:
   ```sql
   UPDATE users SET role = 'staff' WHERE email = 'doctor.test@example.com';
   ```
3. 의료진 계정으로 로그인 → **환자 관리** 페이지가 뜨면 준비 완료

### 테스트용 사진

- png 또는 jpg 사진 1~2장 (스크린샷도 가능)
- 실패 확인용: 10MB 넘는 사진 1장, png·jpg가 아닌 파일 1개 (webp, gif, txt 등)

## 4단계. 진료기록 목록·상세 (REQ-MDR-002, 003)

| # | 할 일 | 기대 결과 |
|---|---|---|
| 4-1 | 홍길순 상세의 진료기록 순서 | **최신순** (CH-20261027-002가 위) |
| 4-2 | 100자 넘는 증상 | 목록에서 `…`로 잘려서 표시 |
| 4-3 | 진료기록 **상세보기** | ⚠️ **"오류 Not Found"** (아래 참고) |
| 4-4 | Swagger `GET /api/v1/medical-records/{record_id}` | 200, 증상 전체 + `xray_image_url` |
| 4-5 | 4-4의 `xray_image_url`을 브라우저 주소창에 입력 | 업로드한 사진이 열림 |

> **4-3이 Not Found인 이유**
> 프론트(`static/pages.js`)는 진료기록 상세와 AI 예측 결과(`GET /medical-records/{id}/analyses`)를 **연달아** 부름.
> AI 예측 결과는 다음 Stage API라 아직 없어서 404 → 화면을 그리기 전에 멈춤.
> 진료기록 상세 API 자체는 정상이라 Swagger로 확인. 화면은 AI 예측 API 이후 확인.
