### 진료기록 상세 화면이 "Not Found"인 이유

- 프론트(`static/pages.js`)는 진료기록 상세(①)와 AI 예측 결과(②, `GET /medical-records/{id}/analyses`)를 **연달아** 부른다.
- ①은 200으로 정상이지만, ②는 다음 Stage API라 아직 없음. ②에서 에러가 나면 화면을 그리기 전에 멈춰서 상세 화면 자체가 보이지 않는다.
- 상세 API는 Swagger로 확인했고, 화면은 AI 예측 API를 만든 뒤 확인

### 통합 테스트에서 발견해 고친 것 (PR #42)

**1. 진료기록 등록 화면 안내 부족**

| 위치 | 전 | 후 |
|---|---|---|
| 차트 번호 placeholder | `차트 번호` | `예: CH-20261027-001 (날짜-순번, 중복 불가)` |
| X-Ray 라벨 | `X-Ray 이미지 업로드` | `X-Ray 이미지 업로드 (png, jpg, 10MB 이하)` |
| 파일 선택 `accept` | `image/*` | `image/png, image/jpeg` |

- 차트 번호가 다른 의료진과 겹치는지 등록 전에는 알 수 없어서, 팀이 같은 형식으로 쓰도록 안내
- `accept`가 `image/*`라 webp·gif도 고를 수 있었고, 서버에서 400이 났다.

**2. 환자 목록에서 성별을 고르면 바로 검색됨**

- 성별·나이 칸에 `onchange` 검색이 걸려 있었다. 값을 바꾸는 순간 검색하면서 화면을 다시 그려서, Tab으로 다음 칸에 넘어갈 수 없었다.
- `onchange`를 빼고 검색 버튼 또는 Enter로 한 번에 검색하게 바꿨다. 이름 → 성별 → 최소 나이 → 최대 나이를 Tab으로 이어서 입력할 수 있다.

**3. 나이·이름 오류가 영어로 표시됨**

- 나이 200을 넣으면 "Input should be less than or equal to 150"이 그대로 뜸. Pydantic 기본 검사(`Field(le=150)`)의 메시지라서....
- users의 `validate_phone`처럼 직접 검사하고 한글 메시지를 냄. 프론트는 `Value error, ` 앞부분을 떼고 보여줌.
  - 나이: "나이는 0세 이상 150세 이하여야 합니다."
  - 이름: "이름은 2자 이상 30자 이하여야 합니다."

**4. 코드 정리 (동작 변화 없음)**

- 파일 중간 import를 맨 위로, 섹션 사이 빈 줄 2줄, 파일 끝 줄바꿈, 타입 힌트, 응답 방식(`-> PatientResponse` + `model_validate`) 통일, 문구 통일("입력해주세요")

### 발견했지만 그대로 둔 것 (조교님 확인 후 다음 Stage)

- **차트 번호 자동 발급**: 비워두면 서버가 `CH-20261027-0001`처럼 발급. 요구사항은 직접 입력이라 확인이 필요.
- **X-Ray 없이 진료기록 등록**: 영상 검사 없이 진료만 하는 경우도 있지만, 요구사항에 X-Ray가 필수로 되어 있다. 바꾸려면 프론트가 빈 파일을 `"undefined"`로 보내는 부분도 고쳐야 하고, 이미지 없는 기록은 AI 예측을 막아야 한다.

## 💡 배운 것

- **DB와 파일은 서로 모르는 사이다.** DB는 `commit` 전에 실패하면 알아서 되돌려지지만, 파일은 그렇지 않다. 그래서 어느 쪽이 실패해도 쓰레기가 남지 않도록 순서를 정해야 한다.
  - 삭제: **DB 먼저**, 성공하면 파일 삭제
  - 등록: **파일 먼저**(DB에 넣을 주소가 필요), DB가 실패하면 파일 삭제
- SQLAlchemy 삭제는 두 가지다. `db.execute(delete(모델).where(...))`는 조건에 맞는 행을 바로 지우고, `db.delete(객체)`는 `select`로 꺼낸 객체를 지운다. 한 번에 섞어 쓰면 안 된다.
- 모델의 `patient_id`는 DB에 있는 **컬럼**(숫자)이고, `patient`는 파이썬에서 연결된 객체로 가는 **relationship**이다. `where`에서 숫자와 비교할 때는 컬럼을 쓴다.
- 데코레이터 괄호 `@router.delete("/{patient_id}")`에는 주소·상태 코드 같은 **설정** 만, 함수 괄호 `def f(patient_id: int, ...)`에는 **받을 재료** 를 쓴다.
- HTTP 에러(404 등)는 service가 내고, repository는 DB 작업만 한다.
- Swagger 테스트로는 프론트의 사용성 문제(검색이 바로 실행됨, 영어 메시지, 형식 안내 부족)가 보이지 않는다. 직접 화면을 써봐야 드러난다.
