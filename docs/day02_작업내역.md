### `app/apis/practice_apis.py` - 회원 관리 실습 API

과제 2. 회원 CRUD API 5개를 한 파일에 작성하고 브랜치 전략에 따라 병합했다.
같은 파일을 4명이 동시에 고쳐야 해서, **뼈대를 먼저 merge하고 담당 영역을 나누는** 방식으로 진행했다.

#### 뼈대 (김지연, PR #4)

- **무엇을**: 팀원이 가져다 쓸 공통 코드와 회원 목록 조회 API
- **어떻게**
  - 과제 제공 `user_list`
  - **공통 검증 타입**: 요구사항 규칙을 한 곳에 모아 생성·수정 API가 함께 쓰도록 함

    | 타입 | 규칙 |
    |---|---|
    | `NameType` | 2-10글자 |
    | `AgeType` | 14세 이상 |
    | `EmailType` | 정규표현식 형식 검사, 최대 30자 |
    | `PasswordType` | 8-20자, 대문자·특수문자 각 1개 이상 |

  - `find_user(user_id)`: 회원 조회와 404 처리를 한 곳에 모음
  - `UserResponse`: 응답 스키마 (password 제외)
  - **회원 목록 조회** `GET /practice_api/users`
  - 담당 API 위치를 주석(`# [A]`, `# [B]`, `# [C]`)으로 나눠, 각자 다른 줄만 수정하도록 함

## 🔍 코드 리뷰로 고친 것 (PR #9)

회원 정보 수정 PR이 정상 수정, 404, 409, 422 테스트를 통과한 상태로 올라왔지만, 요구사항 표와 대조해 직접 실행해보니 3가지 문제가 있었다. **Request changes**로 리뷰를 남겼고, 수정 후 재검토해 승인했다.

| 문제 | 원인 | 수정 |
|---|---|---|
| 빈 요청 `{}`이 200 반환 (요구사항: 400) | 입력값이 없는지 확인하지 않음 | 입력값이 없으면 400 반환 |
| 이름(name)이 수정됨 (요구사항: 나이·이메일·비밀번호만) | 요청 스키마에 `name` 포함 | `UserUpdateRequest`에서 `name` 제거 |
| `{"age": null}` 요청 시 500 에러 | `exclude_unset`은 직접 보낸 null을 그대로 저장 | `exclude_none`으로 None 값 제외 |
